# 요구사항 명세 — 주식 조회·추천·매매 앱

- 작업-ID: 20260725-stock-advisor
- 기준선: 초안 (미승인)
- 작성일: 2026-07-25

## 1. 문제와 목적

사용자는 개인 투자자로서 국내 주식시장(KOSPI/KOSDAQ)을 투자 기간 관점(장기 / 중단기 스윙 / 단타)으로 나누어 관리하고 싶다. 현재는 시장 전체를 훑어 유망 종목을 찾는 일과 보유·관심 종목의 매수/매도/홀딩 판단을 수작업으로 하고 있으며, 이를 키움증권 영웅문 REST API 기반의 앱으로 자동화하려 한다.

**목적**: 시장 스캔 → 전략별 종목 추천, 개별 종목 분석 → 매수/매도/홀딩 의견 제시, 사용자 확인 후 주문 실행까지를 하나의 시스템으로 제공한다.

## 2. 사용자와 사용 환경

- 사용자: 본인 1명 (단일 사용자, 단일 키움 계좌)
- 주 사용 시나리오: **장중 외출 중 핸드폰/태블릿으로 확인**, 귀가 후 PC/태블릿으로 리뷰
- 실행 환경: 백엔드는 상시 구동 가능한 본인 PC(또는 홈서버)에서 실행

## 4. 기능 요구사항

### 공통 기반

- **FR-01** 키움 REST API 인증: 접근토큰 발급(au10001)·만료 전 자동 갱신·폐기. 모의/실전 도메인을 설정으로 전환할 수 있다.
- **FR-02** API 호출 계층: 호출량 제한(rate limit)을 준수하는 요청 큐·스로틀링·연속조회(cont-yn/next-key) 처리를 공통 제공한다.

### 시장 스캔 및 추천 (요구사항 4번)

- **FR-03** 시장 스캔은 깔때기 구조로 동작한다: 랭킹 API(거래량급증, 거래대금상위, 등락률상위, 신고가, 외국인/기관 순매수 등)와 조건검색(ka10171~10172)으로 후보군을 압축한 뒤, 후보 종목만 상세 분석한다. 전 종목 무차별 조회는 하지 않는다.
- **FR-04** 후보 종목을 3개 전략 프로파일(장기/스윙/단타)별 스코어링 모델로 평가하여 전략별 추천 목록(순위 + 점수)을 생성한다.
- **FR-05** 각 추천에는 근거를 함께 표시한다: 어떤 지표가 몇 점을 기여했는지(점수 구성), 핵심 수치(예: PER, 외국인 연속 순매수 일수, 거래량 배율 등).
- **FR-12** 위생 필터: 관리종목, 거래정지, 투자위험/경고 지정 종목, 저유동성 종목(일평균 거래대금 하한 미달)은 모든 전략의 후보에서 제외한다.
- **FR-13** 조건검색식 연동(D-07): 앱은 전략별 권장 조건검색식 정의(HTS 작성 가이드)를 문서로 제공하고, 사용자가 HTS에 등록한 조건식 목록을 조회(ka10171)하여 전략별로 매핑한 뒤 스캔 깔때기의 1차 필터로 사용한다(ka10172).
- **FR-14** 시장 국면 판단: KOSPI/KOSDAQ 지수 추세, 상승/하락 종목 수 등으로 시장 국면(상승/하락/횡보)을 판단해 대시보드에 표시하고, 스윙·단타 프로파일의 추천 강도(추천 개수, 기준 점수)를 국면에 따라 조절한다.

### 개별 종목 분석 (요구사항 5번)

- **FR-06** 사용자가 종목명 또는 종목코드를 입력하면 해당 종목의 시세·차트·수급·기본 지표를 취합하여 3개 전략 관점 각각의 **매수/매도/홀딩 의견 + 근거**를 제시한다.
- **FR-07** 보유 종목(계좌 잔고 kt00018 연동)에 대해서는 매입가·수익률을 반영한 의견(예: 손절/익절 기준 대비 위치)을 제시한다.

### 주문 (D-02)

- **FR-08** 추천 화면·종목 화면에서 매수/매도 주문을 낼 수 있다. 주문은 반드시 수량·가격·예상금액을 보여주는 확인 단계를 거쳐 사용자가 승인한 경우에만 API(kt10000/kt10001)로 전송한다.
- **FR-09** 미체결 조회(ka10075)·정정·취소(kt10002/kt10003), 잔고·예수금 조회를 제공한다.
- **FR-15** 리스크 관리 보조: 주문 확인 단계에서 계좌 평가금액 대비 주문 비중(%)과 전략별 제안 손절가·목표가를 함께 표시한다. 설정된 1회 주문 금액 상한(NFR-02)을 초과하는 주문은 차단한다.

### 모니터링과 알림

- **FR-10** 관심종목 그룹을 관리하고, 관심·보유 종목의 현재가를 장중 주기적으로 갱신하여 대시보드에 표시한다.
- **FR-11** 조건 충족 이벤트(예: 추천 신호 발생, 보유 종목 손절선 도달)를 텔레그램으로 푸시 알림한다. (알림 채널은 D-04 승인에 따름)
- **FR-17** 데일리 브리핑: 장 시작 전(전일 요약, 예상체결 기반 갭 상위 종목, 오늘의 시장 국면)과 장 마감 후(당일 계좌 손익, 추천 성과, 보유 종목 의견 변화) 브리핑을 생성해 텔레그램으로 발송한다.

### 추천 이력과 성과 검증

- **FR-16** 추천 이력 저장·성과 추적: 생성된 모든 추천(종목, 시점, 전략, 점수, 근거)을 저장하고, 추천 이후 경과 수익률(예: 1일/5일/20일)을 추적하여 전략별 적중률·평균 수익률 리포트를 제공한다. 이 데이터는 스코어링 가중치 튜닝의 근거가 된다.

### 배포와 운영 (D-08)

- **FR-18** 배포 구성: Docker Compose 기반 배포 구성을 제공하여 배포 타겟 이전(노트북 → 미니PC)이 데이터 볼륨 복사 + `docker compose up`으로 완료되게 한다. 코드 개발 완료 후 1차 타겟(노트북)에 배포 환경 구축까지 수행한다.
- **FR-19** 백업: 운영 데이터(SQLite DB, 설정)를 매일 자동으로 NAS(DS220j)에 날짜별 사본으로 전송하고 최근 N일치를 보관한다.

## 5. 비기능 요구사항

- **NFR-01 보안**: appkey/secretkey/토큰/계좌번호는 로컬 설정 파일(.env 등)에만 저장하고 저장소에 커밋하지 않는다. 백엔드는 인터넷에 직접 노출하지 않으며(포트포워딩 금지) 원격 접속은 VPN(Tailscale) 경유로만 한다.
- **NFR-02 안전장치**: 실계좌 모드는 명시적 설정 전환으로만 활성화한다. 1회 주문 금액 상한 등 가드레일을 설정할 수 있다.
- **NFR-03 API 준수**: 키움 API 호출량 제한을 초과하지 않는다. 초과 응답(에러) 시 백오프 후 재시도한다.
- **NFR-04 장 운영시간 인지**: 장중/장외/휴장일을 구분하여 스캔·갱신 주기를 조절한다.
- **NFR-05 관측성**: 모든 주문 요청·응답과 추천 생성 이력을 로그로 남겨 사후 검증이 가능하게 한다.
- **NFR-06 데이터 적재**: 조회한 시세(일봉 등)·지표 데이터는 로컬 DB에 적재하여 중복 API 호출을 줄이고, FR-16의 성과 추적과 향후 백테스팅(Phase 2)의 데이터 기반으로 활용한다.

## 7. 제약과 의존성

- 키움 REST API 스펙: [doc/kiwoom-rest-api-spec.json](../../../doc/kiwoom-rest-api-spec.json) (약 300개 API, 실전/모의 도메인)
- 키움 API에는 재무제표 전체가 없음 → 장기 프로파일 1차 버전은 주식기본정보(ka10001)의 요약 지표(PER/PBR/ROE 등)와 수급·추세 지표로 구성한다.
- 시장 전수 조회는 호출량 제한상 불가 → FR-03의 깔때기 구조가 필수 제약.
- 실시간 데이터(단타 프로파일)는 WebSocket TR(0A/0B/0D 등) 사용 — 동시 등록 종목 수 제한 확인 필요(미해결 질문 Q-02).

## 8. 인수 조건 (대표)

- **AC-01** 모의투자 도메인에서 토큰 발급 → 삼성전자(005930) 기본정보 조회가 성공한다.
- **AC-02** "시장 스캔 실행" 시 3개 전략 프로파일별로 각각 N개(설정값) 이하의 추천 목록이 점수·근거와 함께 생성된다.
- **AC-03** 종목코드를 입력하면 3개 관점의 매수/매도/홀딩 의견과 근거 지표가 표시된다.
- **AC-04** 주문 버튼 → 확인 다이얼로그 승인 → 모의계좌에 주문 접수 → 미체결/체결 내역에서 확인된다. 확인 단계 없이 주문이 전송되는 경로가 존재하지 않는다.
- **AC-05** 핸드폰 브라우저(모바일 뷰포트)에서 대시보드·종목 화면·주문 확인 흐름이 정상 동작한다.
- **AC-06** 보유 종목이 설정한 손절 기준에 도달하면 텔레그램 알림이 수신된다.
- **AC-07** 관리종목·거래정지 종목은 어떤 전략의 추천 목록에도 나타나지 않는다.
- **AC-08** HTS에 등록한 조건검색식 목록이 앱에 표시되고, 전략에 매핑하면 해당 조건식 결과가 스캔 후보군에 반영된다.
- **AC-09** 추천 이력 화면에서 과거 추천 각각의 경과 수익률과 전략별 적중률을 확인할 수 있다.
- **AC-10** 1회 주문 금액 상한을 초과하는 주문 시도는 확인 단계에서 차단되고 사유가 표시된다.
- **AC-11** 배포 타겟에서 `docker compose up -d` 한 번으로 전체 시스템이 기동되고, 호스트 재부팅 후에도 자동으로 재기동된다.
- **AC-12** 백업 작업 실행 후 NAS(DS220j)에 당일 날짜의 DB 사본이 생성되어 있다.

## 9. 가정

- A-01: 사용자는 키움 REST API appkey/secretkey를 발급받았거나 발급 가능하다 (모의투자 포함).
- A-02: 백엔드를 상시 구동할 PC/홈서버가 있다.
- A-03: 키움 REST API는 고정 IP 등록 없이 사용 가능하다 (문서 확인 필요 시 Q-03).
