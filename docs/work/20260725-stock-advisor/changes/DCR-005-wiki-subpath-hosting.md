# DCR-005: 위키 하위 경로(/herongs) 호스팅

- 상태: **승인 (2026-09-28)** — 구현·운영 반영 완료(d07deff·7012b00, 2026-09-28 16:52). AC-23~26 통과, **AC-27(위키 경유 관리자 실사용)은 사용자 확인 대기**. 작업 기록: homeserver `docs/work/20260928-herongs-subpath/work-log.md`
- 날짜: 2026-09-28
- 대상 기준선: requirements.md NFR-01, design.md §7 보안·§11 배포, 프론트엔드 빌드 경로, `POST /api/scan` 계약
- 짝 변경: homeserver 저장소 **DCR-010**(위키 인증 프록시) · **ADR-011**(외부 노출 경로)

## 배경

사용자가 HERONGS를 `https://yongs-wiki.com/herongs`로 외부에서 쓰기를 원한다(2026-09-28). 위키는 같은 맥미니에서
Cloudflare Tunnel로 외부에 노출되어 있으므로, **백엔드 위치는 그대로 두고** 위키가 로그인·권한을 판정한 뒤 요청을
HERONGS로 넘기는 구조로 한다(위키 DCR-010). 키움 접속 IP는 바뀌지 않는다.

사용자 결정(2026-09-28): 접근은 관리자 본인만(나중에 STOCK 정회원 조회 확장 가능한 구조), 주소는 하위 경로,
**PIN 유지**, 배포는 대기 중인 변경(조건검색 seq 매칭 40c177f, NAS 백업 전환)과 한 번에.

## 이 저장소에서 바꿔야 하는 이유 (조사 결과)

1. **화면이 `/api/...`를 절대경로로 부른다**(`frontend/src/api.ts`). 하위 경로에서는 `yongs-wiki.com/api/...`로 가서
   **위키의 `/api`(로그인·텔레그램)와 충돌**한다. 빌드 자산(`/assets/...`)도 같은 문제다.
2. **세션 쿠키 `herongs_session`의 경로가 `/`** 라 위키 전 경로에 실려 다닌다.
3. **수동 스캔 `POST /api/scan`이 스캔이 끝날 때까지 응답을 붙잡는다**(수 분). Cloudflare는 100초에 끊으므로(524)
   외부 경로에서는 항상 오류로 보인다.

## 결정

1. **모든 경로를 `/herongs` 아래로 옮긴다.** API `/herongs/api/...`, 화면 `/herongs/`. `/`는 `/herongs/`로 리다이렉트한다.
   `/healthz`는 도커 헬스체크용으로 루트에 남긴다.
   - 위키 프록시는 경로를 **그대로** 넘긴다(접두어 변환 없음). Tailscale 직접 접속도 `macmini:8000/herongs/`로 같은 경로를 쓴다.
     두 입구가 같은 경로 체계를 쓰므로 한쪽만 깨지는 일이 없다.
2. **프론트엔드 기준 경로를 `/herongs/`로** — Vite `base`, API 호출은 기준 경로를 앞에 붙인다. PWA 설치 범위(scope)·시작 URL도 따라간다.
3. **세션 쿠키 `Path=/herongs`** — HERONGS 쿠키가 위키 경로로 새지 않는다.
4. **수동 스캔을 백그라운드 실행으로** — `POST /herongs/api/scan`은 스캔을 시작하고 즉시 `202`를 돌려준다.
   이미 수동 스캔이 진행 중이면 `409`. `GET /herongs/api/scan`이 `{running, finished_at}`을 돌려주고, 대시보드가 이를
   몇 초 간격으로 확인해 끝나면 추천을 다시 불러온다.
5. **PIN 인증은 그대로** — 위키 로그인(관리자) + PIN 이중 확인.

## 요구사항·인수 조건

- **NFR-01 개정**: "백엔드는 인터넷에 직접 노출하지 않으며(포트포워딩 금지) 원격 접속은 VPN(Tailscale) 경유로만 한다"
  → "백엔드는 인터넷에 직접 노출하지 않는다(포트포워딩·터널 직결 금지). 원격 접속은 **VPN(Tailscale) 또는 위키 인증
  프록시**(`yongs-wiki.com/herongs`, 위키가 관리자 판정을 통과시킨 요청만) 경유로만 한다."
- **FR-28** HERONGS는 `/herongs` 하위 경로에서 동작하며, 위키 인증 프록시와 Tailscale 직접 접속이 같은 경로 체계를 쓴다.
- **FR-29** 수동 스캔은 백그라운드로 실행되고, 시작 요청은 즉시 응답하며, 진행 상태를 조회할 수 있다.
- **AC-23** 화면과 모든 API가 `/herongs/` 아래에서 동작한다(Tailscale `:8000/herongs/`와 위키 경유 양쪽).
- **AC-24** `/` 요청은 `/herongs/`로 리다이렉트된다. `/healthz`는 루트에서 계속 200이다.
- **AC-25** PIN 로그인 후 받은 세션 쿠키의 `Path`가 `/herongs`다.
- **AC-26** `POST /herongs/api/scan`은 수 초 안에 `202`를 돌려주고, 진행 중 재요청은 `409`, 완료 후 `GET`은 `running=false`다.
- **AC-27** 위키 경유로 관리자가 PIN 로그인 → 추천 조회 → 수동 스캔 → 주문 미리보기까지 수행된다(위키 AC-28과 같은 시나리오).

## 대안

| 대안 | 판단 |
|---|---|
| 위키 프록시가 `/herongs` 접두어를 떼고 HERONGS는 루트에 둔다 | 기각 — 화면 빌드는 `/herongs/` 기준이어야 하므로 Tailscale 직접 접속(루트)에서 자산 경로가 깨진다. 두 입구가 다른 경로를 쓰게 된다 |
| FastAPI `root_path`만 설정 | 기각 — 프록시가 접두어를 떼는 구조를 전제한다. 위와 같은 이유 |
| 수동 스캔을 그대로 두고 Tailscale에서만 쓰기 | 기각 — 외부 경로에서 대시보드의 핵심 버튼이 항상 오류로 보인다 |

## 마이그레이션과 롤백

- **데이터 변경 없음.**
- **사용자 조치**: 폰 홈 화면의 HERONGS 아이콘(PWA)은 옛 주소(`:8000/`) 기준이라 **다시 설치**해야 한다 — 새 주소
  `yongs-wiki.com/herongs` 또는 `macmini:8000/herongs/`에서 "홈 화면에 추가". 기존 PIN 세션은 쿠키 경로가 바뀌어
  한 번 다시 로그인해야 한다.
- **롤백**: 이 변경 커밋을 되돌려 재배포하면 루트 경로로 돌아간다. 위키 쪽은 DCR-010 롤백(라우트 폴더 삭제)과 짝으로 한다.

## 결과와 단점

- 같은 출처(`yongs-wiki.com`)에서 HERONGS 스크립트가 실행된다 — 위험과 완화는 위키 ADR-011에 기록.
- 수동 스캔과 정기 스캔(스케줄러)이 겹치는 것은 지금도 가능하며 이번에 바꾸지 않는다(수동끼리만 막는다).
- 종목 분석(`/stocks/{code}/analysis`)은 키움 응답이 느린 시간대에 수십 초가 걸릴 수 있어, 위키 프록시 제한(60초)에
  걸리면 504가 난다. 발생하면 별도로 다룬다.
