# DCR-001: 로그인 시도 제한 (무차별 대입 방어)

- 상태: 승인 (2026-08-03, 사용자 작업 지시로 방향 확정)
- 날짜: 2026-08-03
- 대상 기준선: design.md §7 보안 설계 (v1)
- 관련 항목: plan.md 후속 작업 "로그인 실패 시도 제한"

## 배경

`/api/auth/login`은 PIN(숫자 6자리) 검증에 시도 횟수 제한이 없어 무차별 대입이
이론상 가능하다. Tailscale이 1차 방벽이라 위험은 낮으나 심층 방어로 보강한다.

## 요구사항 (경량)

- **FR-SEC-01** 로그인 연속 실패가 5회에 도달하면 이후 로그인 시도를 300초 동안
  거부한다(HTTP 429, 남은 시간 안내). 잠금 중에는 올바른 PIN도 거부한다.
- **FR-SEC-02** 로그인 성공 시 실패 카운터를 초기화한다.
- **AC-SEC-01** 오답 5회 → 6번째 시도(정답 포함)가 429. 잠금 만료 후 정답 로그인 성공.
- **AC-SEC-02** 오답 4회 후 정답 성공 → 카운터 리셋(이후 오답 1회는 401, 잠금 아님).

## 고려한 대안

| 대안 | 판단 |
|---|---|
| 실패마다 지연(sleep) | 동기 라우트라 threadpool 워커를 점유, 오히려 DoS 표면 증가 — 기각 |
| IP별 카운터 | Tailscale 뒤 단일 사용자 환경에서 IP 구분 무의미, IP 회전 우회 여지만 생김 — 기각 |
| **전역 카운터 + 잠금 (선택)** | 인메모리 dict(`st.sessions`)와 동일한 수명 주기, 최소 구현. 공격자에 의한 본인 잠금(DoS)은 Tailscale 뒤라 수용 |

## 결정

- `app.state.login_attempts = {"fails": 0, "locked_until": 0.0}` — 세션과 같은
  인메모리 상태(재기동 시 초기화, 수용).
- 5회 연속 실패 → 300초 잠금. 잠금 중 429 + 남은 시간. 성공 시 리셋.
- PIN 비교를 `secrets.compare_digest`로 전환(타이밍 공격 방어, 1줄 보강).

## 결과와 단점

- 재기동으로 잠금이 풀린다 — 세션도 같은 특성이며 단일 사용자 로컬 운영이라 수용.
- design.md §7에 본 결정을 반영한다.
