# DCR-002: 정정 주문 가드레일 적용

- 상태: 승인 (2026-08-03, DCR-001 작업 중 발견한 가드레일 우회 경로 봉합)
- 날짜: 2026-08-03
- 대상 기준선: design.md §7 보안 설계 (v1), §5.3 주문 2단계 흐름
- 관련 항목: plan.md 후속 작업 "주문 정정 API 노출" 비고

## 배경

`PUT /api/orders/{ord_no}`(정정, DCR-001과 같은 날 노출)는 preview/confirm
경로를 거치지 않아, 정정으로 수량·가격을 올리면 1회 주문 금액 상한(AC-10)을
우회할 수 있다. 일일 누적 집계(`_today_order_total`)에도 정정분은 빠져 있다.

## 요구사항 (경량)

- **FR-SEC-03** 정정 주문 금액(수량×가격)이 1회 주문 금액 상한을 초과하면
  전송하지 않고 사유와 함께 거부한다(422). 수량·가격 0 이하도 거부한다.
- **AC-SEC-03** 상한 초과 정정 요청 → kt10002 미호출, 422 + "상한" 사유 표시.

## 고려한 대안

| 대안 | 판단 |
|---|---|
| 정정도 preview/confirm 2단계로 | 이미 승인·접수된 주문의 조정에 2단계는 과함. UI·상태 관리 복잡도 대비 이득 없음 — 기각 |
| 일일 누적에 정정분 반영 | 정정은 기존 주문의 대체라 전액 가산은 이중 계산. 차액 계산은 원주문 조회(ka10075)가 필요해 복잡 — 기각. 일일 상한은 원주문 제출 시점에 이미 검사됐고, 정정으로 늘릴 수 있는 노출은 주문당 1회 상한 이내로 제한됨 |
| **정정에 1회 상한만 직접 검사 (선택)** | preview와 같은 검사식·메시지 재사용, 최소 변경으로 우회 경로 봉합 |

## 결정

- `OrderService.modify()` 진입부에서 수량·가격 양수 검사 + 1회 주문 금액 상한
  검사(`GuardrailError`, preview와 동일 메시지 형식).
- 라우트는 preview/confirm과 동일하게 `GuardrailError → 422` 매핑.
  PWA는 기존 orderError 표시로 사유 노출(추가 변경 없음).

## 결과와 단점

- 반복 정정으로 일일 누적 노출을 늘릴 수 있으나 주문당 1회 상한 이내 —
  단일 사용자 개인 앱에서 수용. design.md §7 가드레일 항목에 반영.
