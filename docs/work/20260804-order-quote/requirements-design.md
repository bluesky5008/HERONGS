# 매매 화면 주문 보조 정보 — 요구사항·설계

- 기준선: **v1 (승인: 2026-08-04)** / 작성일 2026-08-04
- 상위 기준선: `docs/work/20260725-stock-advisor/{requirements,design}.md`
- 영향: 상위 설계 §4.1(키움 TR 매핑), §4.2(내부 REST API) 확장 — 승인 시 상위 문서 갱신

## 1. 배경과 문제

2026-08-03~04 실사용(모의계좌, 폰 PWA)에서 사용자가 다음 불편을 보고했다.

- **매수 시**: 주문창에 대상 종목의 현재가와 내 잔여 예산이 없어, 얼마에 몇 주를 살지 판단하려면 다른 화면·앱을 봐야 한다.
- **매도 시**: 해당 종목의 보유 수량이 표시되지 않아 몇 주를 팔 수 있는지 알 수 없다.
- 매수·매도 모두 **호가 정보**가 없어 "지금 넣으면 체결될 가격"을 가늠할 수 없다.

핵심 문제는 **주문창이 가격·수량 입력을 요구하면서 그 판단에 필요한 정보를 제공하지 않는다**는 것이다.
2026-08-04 실검증에서 정정 1차 시도가 상/하한가 오류(RC4027)로 거부된 것도 같은 원인에 해당한다.

## 2. 현재 상태 조사 (확인된 사실)

### 2.1 화면

- 주문창 `frontend/src/views/OrderDialog.tsx`는 `side/code/name/profile`만 받는다. 입력 전 표시 정보는 없다.
- 주문창은 두 곳에서 열린다: `Dashboard.tsx`(추천 목록), `StockView.tsx`(종목 분석).
- preview 응답에는 예상금액·비중·손절/목표가가 있으나, **가격을 입력한 뒤에야** 보이므로 입력 보조가 되지 못한다.

### 2.2 백엔드 (기존 자산)

- `OrderService.holdings()` — kt00018로 `{code: Holding(avg_price, qty)}` 반환. **구현·사용 중**(분석 API가 사용).
- `OrderService.deposit()` — kt00001 호출, `entr`(예수금)만 반환. **구현돼 있으나 호출부가 한 곳도 없음**(미노출 사장 코드).
- `ka10001`은 이미 TR 매핑·사용 중이나, 현재가 필드를 추출하지 않는다.
- 호가 조회 TR은 매핑·구현되어 있지 않다. 상위 설계 §4.1은 호가를 **WS 실시간(0D)** 으로만 다룬다.

### 2.3 키움 TR 실검증 (2026-08-04 12:xx, 모의 도메인 실호출로 확인)

| TR | 경로 | 확인 결과 |
|---|---|---|
| `ka10001` | `/api/dostk/stkinfo` (기매핑) | `cur_prc`(현재가, 부호 포함 `-230250`), `base_pric`(기준가), `flu_rt`(등락률), `open/high/low_pric` 제공 |
| `kt00001` | `/api/dostk/acnt` (기매핑) | `entr`(예수금 500,000,000), **`ord_alow_amt`(주문가능금액 499,994,528)**, 증거금율별(`100stk_ord_alow_amt` 등) 제공 |
| `ka10004` | `/api/dostk/mrkcond` (**신규**) | **존재·동작 확인**. 10단 호가 69필드 |

`ka10004` 필드 규칙 (실응답에서 확인):

- 매도 1단 `sel_fpr_bid`/`sel_fpr_req`, 2~10단 `sel_{n}th_pre_bid`/`sel_{n}th_pre_req`
- 매수 1단 `buy_fpr_bid`/`buy_fpr_req`, 2~10단 `buy_{n}th_pre_bid`/`buy_{n}th_pre_req`
- 총잔량 `tot_sel_req`/`tot_buy_req`, 기준시각 `bid_req_base_tm`(`131243` = 13:12:43), 시간외 `ovt_*`
- **주의**: 1단만 `fpr`(최우선) 접두어로 규칙이 다르다. 가격에 등락 부호가 붙으므로 절댓값 처리가 필요하다(`ScalpSignalHandler`의 기존 처리와 동일).
- `ka10004`는 현재가를 포함하지 않으므로 현재가는 `ka10001`에서 얻어야 한다.

### 2.4 해석

- 사용자가 말한 "예상 체결 가격"은 **최우선 호가**로 충족된다: 즉시 매수 체결가 = 최우선 매도호가, 즉시 매도 체결가 = 최우선 매수호가. (장전 예상체결가 TR은 상위 계획의 별도 미해결 항목이며 이 작업의 범위 밖이다.)
- "잔여 예산"은 예수금(`entr`)이 아니라 **주문가능금액(`ord_alow_amt`)** 이 정확하다. 예수금은 미수·증거금을 반영하지 않는다.

## 3. 요구사항

상위 요구사항 명세의 번호를 이어서 부여한다(기존 최대: FR-19, AC-12).

### 기능 요구사항

- **FR-20** 주문창은 대상 종목의 **현재가**(등락률 포함)를 입력 전에 표시한다.
- **FR-21** 주문창은 **호가 정보**(매도·매수 각 5단의 가격과 잔량, 총잔량, 호가 기준시각)를 표시한다. 매수·매도 화면 모두 동일하게 제공한다.
- **FR-22** **매수** 시 **주문가능금액**을, **매도** 시 해당 종목의 **보유 수량**을 표시한다.
- **FR-23** 표시된 현재가·호가 가격을 탭하면 가격 입력란에 그 값이 채워진다. (사용자 요청의 "가격 입력이 수월할 것" 을 직접 충족하는 최소 수단)
- **FR-24** 현재가와 호가는 주문 **입력 단계에서 자동으로 갱신**된다. 갱신은 다음 조건에서 중지한다: ① preview·confirm 단계로 진입 ② 창을 연 뒤 무입력 3분 경과 ③ 화면이 비활성(백그라운드·화면 꺼짐). 중지 상태는 화면에 표시하고 수동 재개 수단을 제공한다.

### 비기능 요구사항

- **NFR-07** 보조 정보 조회 실패가 주문 기능 자체를 막지 않는다. 조회에 실패한 항목만 실패 표시하고, 가격·수량 입력과 preview/confirm은 그대로 동작한다.
- **NFR-08** 주문창을 여는 동작으로 발생하는 키움 TR 호출은 4회를 넘지 않는다. 자동 갱신(FR-24) 1회는 **시세·호가 2개 TR만** 사용하고 계좌 조회를 반복하지 않으며, 갱신 주기는 3초로 한다.
  - 근거(2026-08-04 실측): 운영 중 실제 호출량은 분당 평균 53회(최근 60분 3,170회)이고 클라이언트 스로틀 한도는 전역 5회/초(분당 300회)·TR별 1회/초다. 3초 주기 폴링은 분당 40회를 더해 총 93회/분(한도의 31%)이 되어 여유가 충분하다. `ka10004`는 TR별 게이트가 스캔용 TR과 분리되어 서로 지연시키지 않는다.

### 인수 조건

- **AC-13** 장중에 종목의 매수 주문창을 열면, 가격을 입력하기 전에 현재가·등락률·주문가능금액·호가 5단이 표시된다.
- **AC-14** 보유 종목의 매도 주문창을 열면 해당 종목의 보유 수량이 표시되고, 미보유 종목에서는 0으로 표시된다.
- **AC-15** 호가의 특정 가격을 탭하면 가격 입력란이 그 값으로 채워지고, 이어서 preview가 그 값으로 수행된다.
- **AC-16** 키움 조회가 실패하거나 장외로 호가가 비어 있어도 주문창은 열리며, 해당 영역만 안내 문구가 표시되고 주문 흐름은 계속 진행된다.
- **AC-17** 입력 단계에서 호가 기준시각이 3초 주기로 갱신되고, ① 주문 확인(preview) 진입 ② 3분 방치 ③ 화면 비활성 각각에서 갱신이 멈추며 멈춘 상태가 화면에 표시된다. 갱신 요청은 계좌 조회 없이 시세·호가만 호출한다(백엔드 로그의 TR 호출로 확인).

### 범위 밖

- 호가 **실시간 스트리밍**(WS 0D 구독) — 갱신은 REST 폴링(FR-24)으로 한정하고 WS 구독은 넣지 않는다(§6 결정 D-2).
- 장전 예상체결가 TR 매핑 — 상위 계획의 별도 항목으로 유지.
- 호가창에서의 원클릭 주문(가격 탭 = 즉시 주문) — 2단계 승인 원칙(FR-08, AC-04)과 충돌하므로 제외. 탭은 입력란 채우기까지만 한다.
- 10단 호가 표시, 체결강도·거래원 등 추가 시세 정보.

## 4. 설계

### 4.1 인터페이스 (상위 설계 §4.2 확장)

```text
GET /api/stocks/{code}/quote                     주문 보조 정보 (FR-20/21/22)
GET /api/stocks/{code}/quote?with_account=false  시세·호가만 (FR-24 자동 갱신용, 2 TR)
```

`with_account`(기본 `true`)가 `false`면 계좌 조회(kt00018·kt00001)를 생략하고
`holding_qty`·`orderable_cash`를 `null`로 반환한다. 자동 갱신은 이 형태만 사용한다(NFR-08).

응답:

```jsonc
{
  "code": "005930",
  "name": "삼성전자",
  "cur_price": 230250,          // ka10001 cur_prc, 절댓값
  "change_rate": -3.86,         // ka10001 flu_rt
  "base_price": 239500,         // ka10001 base_pric (전일 기준가)
  "holding_qty": 0,             // kt00018, 미보유 시 0
  "orderable_cash": 499994528,  // kt00001 ord_alow_amt
  "orderbook": {                // ka10004, 조회 실패 시 null
    "base_time": "13:12:43",
    "asks": [{"price": 230500, "qty": 31576}, ...],  // 5단, 1단(최우선)부터
    "bids": [{"price": 230000, "qty": 17889}, ...],
    "total_ask_qty": 148667,
    "total_bid_qty": 941529
  },
  "errors": ["orderbook"]       // 부분 실패 항목 (NFR-07), 없으면 빈 배열
}
```

- 인증은 기존 `_auth`와 동일(세션 필수).
- 부분 실패: 네 조회를 개별적으로 감싸 실패한 항목만 `null`/`0`으로 두고 `errors`에 이름을 넣는다. 전체 실패해도 200을 반환한다(NFR-07). 키움이 거부한 경우의 전역 502 핸들러와 달리, 이 엔드포인트는 **주문창을 열 수 있어야 하므로** 자체적으로 흡수한다.

### 4.2 백엔드 컴포넌트

| 위치 | 변경 |
|---|---|
| `kiwoom/client.py` | `TR_PATHS`에 `ka10004: /api/dostk/mrkcond` 추가 |
| `services/orders.py` | `deposit()`를 `orderable_cash`(ord_alow_amt) 반환으로 확장 — 기존 미사용 코드이므로 호출부 파급 없음 |
| `services/quotes.py` **(신규, 소형)** 또는 `collector.py` | `ka10001` 시세 추출 + `ka10004` 호가 파싱(1단 `fpr` 예외 규칙, 절댓값 처리) |
| `api/routes.py` | `GET /stocks/{code}/quote` — 4개 조회를 `asyncio.gather(..., return_exceptions=True)`로 병렬 수행 후 조립 |

배치 위치는 구현 시 결정한다(결정 사다리: 기존 `collector`에 붙일 수 있으면 새 모듈을 만들지 않는다).

### 4.3 화면 (OrderDialog)

입력 단계 상단에 보조 정보 블록을 추가한다. preview·confirm 단계 화면은 **변경하지 않는다**(AC-04로 검증된 2단계 흐름 유지).

```text
┌ 삼성전자 매수 ───────────────────────┐
│ 현재가 230,250 (-3.86%)   ● 자동갱신 │   ← 중지 시 "갱신 멈춤 [재개]"
│ 주문가능 499,994,528원               │   ← 매수. 매도면 "보유 3주"
│ ─ 호가 (13:12:43) ─────────────────  │
│   매도5  231,500   14,622            │   ← 탭 → 가격 입력 (FR-23)
│   ...                                │
│   매도1  230,500   31,576            │
│   매수1  230,000   17,889            │
│   ...                                │
│   총 매도 148,667 / 매수 941,529     │
│ [수량] [가격]                        │
│ [주문 확인]                          │
└──────────────────────────────────────┘
```

- 주문창을 열 때 전체(4 TR)를 1회 조회하고, 이후 입력 단계에서는 3초 주기로 시세·호가만 갱신한다(FR-24, NFR-08).
- 갱신 중지 조건(preview 진입 / 3분 방치 / 화면 비활성)에서 타이머를 정리하고 "갱신 멈춤 · [재개]"로 전환한다. 갱신 요청이 실패해도 직전 값을 유지하며, 연속 실패 시 중지하고 같은 표시로 전환한다.
- 호가 기준시각을 함께 표시해 정보의 신선도를 사용자가 판단할 수 있게 한다(자동 갱신이 멈춘 것을 사용자가 즉시 알 수 있는 2차 수단).
- 조회 실패·장외로 호가가 없으면 그 영역에 "호가 정보 없음(장외)" 문구만 표시한다(AC-16).

## 5. 실패·경계 시나리오

| 상황 | 동작 |
|---|---|
| 호가 조회 실패/장외 | `orderbook: null` → 해당 영역만 안내 문구, 주문은 정상 진행 |
| 잔고·예수금 조회 실패 | 해당 값 미표시, 주문은 정상 진행 |
| 미보유 종목 매도 | 보유 0 표시. 주문 자체는 차단하지 않음(키움이 거부하며, 그 사유는 502 핸들러로 표시) |
| 종목코드 오류 | 기존 분석 화면과 동일하게 키움 오류가 502+사유로 표시 |

## 8. 가정·미해결 질문·위험

**가정 (낮은 위험, 명시 후 진행)**

- A-1 `ka10004`는 모의·실 도메인에서 동일하게 동작한다(모의에서만 실검증).
- A-2 장외에는 호가 잔량이 0이거나 직전 값으로 응답한다 — 기준시각 표시로 사용자가 판별 가능.

**미해결 질문 (구현 시 확인)**

- Q-A **매도 가능 수량**: 현재 설계는 보유 수량(`rmnd_qty`)을 표시한다. 미체결 매도 주문이 걸린 수량은 차감되지 않는다. kt00018 행에 주문가능수량 필드가 있으면 그것을 우선 사용한다(현재 보유 0이라 필드 확인 불가).
- Q-B `ka10004`의 연속조회·유량 특성 미측정 — NFR-08의 보수적 정책으로 회피.

**위험**

- R-1 (낮음) 자동 갱신에 의한 유량 증가. 실측상 한도의 31% 수준이며(NFR-08), 중지 조건 3종으로 방치 폴링을 막는다. 다만 **중지 로직이 빠지면 창을 열어둔 채 방치할 때 하루 2만 건 규모의 호출이 발생**하므로, FR-24의 중지 조건은 구현·검증에서 생략하지 않는다.
- R-2 (낮음) 호가 파싱 규칙(1단 `fpr` 예외)을 놓치면 최우선 호가가 누락된다 — 단위 테스트로 고정한다.
